# Worker 事件循环与 persondog 后处理优化验证

## 改动

- EOS 图片下载完成后的 `cv2.imdecode` 改由现有 I/O 线程池执行，不新增线程池、配置或依赖。
- YOLOv5 NMS 前按本次请求的最低置信度预过滤，不再将全部低分候选框送入 NMS。
- 考虑 `BoundingBox` 会把置信度四舍五入到两位小数，预过滤额外保留 0.005 的边界区间，防止改变现有结果。
- 保留原来的跨类别抑制方式、IoU、输出顺序和最终逐标签置信度过滤。不同标签阈值不合并成一个最终阈值。
- 删除一次重复的 `as_numpy` 输出反序列化。

## 回归测试

先确认旧代码在“解码不能阻塞事件循环”“输出只反序列化一次”“NMS 使用请求阈值”三项测试失败，再实施修改；之后补充四舍五入边界测试，先复现漏框，再保留边界候选框。

本地以及生产原镜像 `aisfh5.com:9091/nexusai/nexusai-inference:v20260923171239` 的一次性、无网络测试容器中，各通过 15 项测试：

```bash
python -m unittest tests.test_worker_image_loading tests.test_yolov5_postprocess tests.test_inference_server tests.test_worker_project_boundary tests.test_github_actions_workflow -v
python -m compileall -q inference api tools utils worker_main.py
git diff --check
```

覆盖：解码在线程中执行且其他协程能继续运行、下载超时、无效图片、多标签低阈值、零/负阈值兼容、四舍五入边界、重复分数、随机候选框、原有跨类别抑制、Worker 容量拒绝及优雅摘流。

CI 已加入这两个新测试模块。

## 真实模型输出的离线后处理比较

在丽水 GPU2 读取 3 张近期图片，每张仅额外执行一次 persondog 推理，保存原始输出后在一次性无网络容器中离线比较。没有写 Kafka、没有向量入库，也没有替换在线 Worker。

每份输出包含 25200 个原始候选框。每种实现重复 3 次，记录中位数；下表为 3 份输出的范围。

| 置信度 | 原后处理 | 优化后处理 | 预过滤后候选数 | 最终结果 |
|---|---:|---:|---:|---|
| 0.2 | 55.734–64.740 ms | 0.127–0.520 ms | 0–18 | 完全一致 |
| 0.5 | 50.770–62.273 ms | 0.113–0.156 ms | 0 | 完全一致 |
| 0.8 | 48.608–77.010 ms | 0.114–0.270 ms | 0 | 完全一致 |

非空结果在 0.2 阈值样本中也一致；更密集目标和特殊边界由确定性及随机回归覆盖，但仍需线上灰度补充场景验证。

重跑工具：`tests/performance/benchmark_persondog_postprocess.py`，输入为保存了 `output_0`、`width_0`、`height_0` 等字段的 NPZ。

```bash
python tests/performance/benchmark_persondog_postprocess.py /path/to/real-model-outputs.npz
```

## 交付与限制

独立分支：`codex/worker-event-loop-postprocess`，工作区 `NexusAi-Worker-perf`。原 Worker 项目的工作区及其未跟踪文件未动。

只证明了后处理单项提速和解码不再同步阻塞事件循环，不代表端到端延迟已经达到某个值，也不能据此宣称全平台积压已解决。未做持续流量 A/B、未构建新生产镜像、未灰度发布。

远端测试材料保留于 `/ai/chen/code/kafka/.worker-opt-20261014`，目录仅 root 可访问；不包含修改后的在线容器配置。
